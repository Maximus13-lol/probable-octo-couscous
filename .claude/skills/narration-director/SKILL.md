# narration-director (`src/narration.py`, конфиг `config/voice.json`, словарь `stress_dict.json`)

Шаг между storyboard и картинками. Для каждой сцены готовит `display_text` (с «ё», для субтитров),
`ssml`, запасной `plain_ssml` и `pause_after_ms` (пауза перед следующей сценой — её применяет сборка).

## Ударения и «ё»
1. RUAccent (`ruaccent`, модели MIT с Hugging Face, кэш `.cache/ruaccent`) размечает сцену целиком —
   контекст нужен для омографов (за́мок/замо́к, му́ка/мука́). Результат: «+» перед ударной гласной, «ё».
2. Слова сопоставляются с текстом через `difflib` (без «+», ё→е).
3. Омографы решаются **голосованием** (`resolve_homographs`): RUAccent (контекст), Gemini (контекст; отвечает
   самим словом с заглавной ударной буквой, варианты перемешаны; «ленивые» ответы на одной позиции у ≥6 слов
   отбрасываются) и словарь Vosk (самый вероятный вариант). Большинство; при ничьей — RUAccent.
   Протокол — `output/<run>/homographs.json`. Урок 11.11.2026: Gemini, выбиравший номер варианта, перебил верные
   решения RUAccent («леса́», «году́», «пропада́ют») — поэтому одному Gemini больше не доверяем.
4. `stress_dict.json` перекрывает RUAccent: `{"слово": "сл+ово"}`, можно задать «ё» (`"все": "всё"`).
   **Когда пользователь жалуется на ударение — добавь слово сюда.** Ключ — форма слова как в тексте.
5. Режим `stress.mode`: `homographs` (по умолчанию — ударения только у омографов и слов из словаря,
   остальное Azure читает сам) или `all`.
6. Способ передачи: для Vosk — «+» перед гласной (`vosk_clean`, проверено: «зам+ок» звучит иначе, чем «замок»);
   для Azure/Gemini TTS — `U+0301` после ударной гласной (`stress.method: acute`). Проверено на нейродвижке
   Microsoft: «за́мок» и «замо́к» синтезируются по-разному (спектральное расстояние ~145 против шума 14–32,
   длительность слова 0.400 / 0.437 с), слово остаётся одним WordBoundary. Знак «+» НЕЛЬЗЯ: синтезатор
   разбивает слово («з», «+», «амок»). `<phoneme>` не используется: для ru-RU нужна полная IPA-транскрипция.
   Проверка на реальном Azure: `python -m src.voice_test --stress-test` (или workflow «Voice test»).
7. Совместимость: `_patch_onnx_inputs` подставляет `token_type_ids`, которые свежий transformers не отдаёт.

## Интонации и паузы
- Gemini как режиссёр возвращает **JSON** (не сырой SSML): фрагменты сцены, `pause_after_ms`, `rate`, `pitch`,
  `emphasis` (ключевые слова), `role` сцены и паузу после сцены. Код сам собирает SSML — так текст
  гарантированно дословный (иначе разъедутся субтитры), а разметка всегда валидна.
- Рамки (`config/voice.json → pauses_ms`): 300–600 мс после хука, перед поворотом и перед развязкой;
  150–250 мс между смысловыми частями. Темп −5…−12% в напряжённых местах, высота +4…+8% в вопросах
  (`limits` ограничивает значения).
- Ключевые слова: `emphasis: prosody` (темп −12%, высота +4%, громкость +15% — работает с любым голосом)
  или `emphasis` (тег `<emphasis>`, Azure поддерживает его не для всех голосов).
- `mstts:express-as` — только если стиль есть в `StyleList` голоса (список берётся из API Azure);
  у русских голосов стилей обычно нет → только prosody.
- `mstts:silence` Leading/Tailing-exact 50 мс — точные края, паузы между сценами задаёт сборка.
- Без Gemini работает `rule_director` (паузы по предложениям, после хука, перед «Но/Однако…» и развязкой).

## Vosk
- `vosk_segments`: фрагменты сцены → текст с «+», темп `rate`, пауза `pause_after_ms`. Выделение ключевых
  слов и высота Vosk не поддерживаются. Артефакт — `narration/vosk_script.txt`.

## Gemini TTS
- `build_tts_text`: дословный текст + `<short pause>` (120–299 мс) / `<long pause>` (≥300 мс) + ключевые слова
  ЗАГЛАВНЫМИ (`gemini.emphasis: caps`) + ударения U+0301. Темп/высоту по фрагментам Gemini TTS не принимает —
  они выражаются через общую манеру `tts_style` (её пишет режиссёр по-английски или берётся
  `GEMINI_DEFAULT_STYLE`; свою можно задать в `config/voice.json → gemini.style`).
- `validate_tts_text`: без тегов текст совпадает со сценой, других тегов нет; иначе — текст без разметки.
- Работает ли U+0301 в Gemini TTS — проверять `python -m src.voice_test --stress-test`; если мешает —
  `stress.method: none`.

## Валидация и откат
`validate_ssml`: XML парсится, только разрешённые теги, корректные `break`/`prosody`, текст совпадает
со сценой. Ошибка → `plain_ssml` (текст с «ё» и ударениями + паузы между предложениями). Если Azure
отверг SSML (BadRequest) — `tts.py` повторяет с `plain_ssml`.

## Артефакты
`output/<run>/narration/scene_XX.ssml`, `narration/full.ssml.txt` (вся разметка с паузами между сценами),
`narration/gemini_tts_script.txt` (манера + текст для Gemini TTS), `narration.json` (голос, стили, режиссёр, ударные слова, слова с «ё»).
