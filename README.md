# Автоматический конвейер YouTube Shorts (тайны и загадки)

Раз в день GitHub Actions сам находит трендовую тему, пишет историю на русском, рисует картинки,
озвучивает, накладывает субтитры и музыку, (по желанию) вставляет рекламный баннер и публикует
вертикальное видео 1080×1920 ~60 с на YouTube. Используются **только бесплатные сервисы**.

```
trend-scout → story-writer → storyboard → narration-director → картинки → озвучка → субтитры → сборка → ad-inserter → publisher
```

| Шаг | Модуль | Сервис |
|---|---|---|
| Поиск темы | `src/trends.py` | YouTube Data API, Reddit JSON, Google Trends (pytrends), Gemini |
| История 130–160 слов | `src/story.py` | Gemini API (бесплатный ключ) |
| Раскадровка 8–12 сцен | `src/storyboard.py` | Gemini API |
| Ударения, «ё», паузы, интонации → SSML | `src/narration.py` | RUAccent + Gemini |
| Картинки | `src/images.py`, `src/style.py` | Pollinations.ai (без ключа) |
| Озвучка | `src/tts.py` | **Vosk TTS** (локально, бесплатно, без ключей, голос 3); запасные — Gemini TTS, Azure |
| Тайминги слов | `src/align.py` | faster-whisper (MIT), локально в Actions |
| Субтитры | `src/subtitles.py` | из таймингов слов |
| Сборка | `src/assemble.py` | MoviePy + FFmpeg, музыка из `music/` |
| Реклама (выкл.) | `src/ads.py` | FFmpeg overlay |
| Публикация | `src/upload.py` | YouTube Data API v3 (OAuth) |

Описание каждого шага для Claude Code — в `.claude/skills/<имя>/SKILL.md`.

## Структура

```
src/            код конвейера (main.py — точка входа)
config/         publish.json — шаблоны публикации; voice.json — голос, ударения, паузы
stress_dict.json словарь исключений ударений (дописывайте сюда)
music/          ваши лоу-фай треки (mp3/wav/ogg/m4a)
ads/            config.json (кампании), баннеры, log.json (показы)
output/         результаты запусков (в git не попадают)
used_topics.json, publish_log.json, trends_quota.json — состояние, коммитится ботом
.github/workflows/daily.yml — расписание
```

## 1. Быстрый локальный тест (без ключей)

Нужны Python 3.11+ и FFmpeg.

```bash
pip install -r requirements.txt
python -m src.main --no-upload
```

Без `GEMINI_API_KEY` конвейер работает в демо-режиме (готовая история про маяк Фланнан, режиссура
по правилам). Озвучка Vosk работает без всяких ключей. Видео: `output/<дата_время>/final.mp4`,
разметка озвучки: `output/<дата_время>/narration/`.

При первом запуске скачиваются модели RUAccent (~500 МБ), faster-whisper small (~500 МБ) и Vosk (~750 МБ).

Флаги:

| Флаг | Что делает |
|---|---|
| `--no-upload` | всё, кроме загрузки на YouTube |
| `--test-ad` | вставить тестовую рекламу (подразумевает `--no-upload`) |
| `--ad-campaign ID` | принудительно взять конкретную кампанию |
| `--topic "..."` | задать тему вручную, без trend-scout |
| `--mark-used` | записать тему в `used_topics.json` даже при `--no-upload` |
| `-v` | подробный лог |

## 2. Ключи и секреты — пошагово

Все секреты добавляются в репозиторий: **GitHub → Settings → Secrets and variables → Actions → New repository secret**.

| Секрет | Обязателен | Для чего |
|---|---|---|
| `GEMINI_API_KEY` | да | тема, история, раскадровка, режиссура, проверка ударений омографов; запасная озвучка |
| `OPENROUTER_API_KEY` | нет, но **рекомендуется** | запасной поставщик текстов: если Gemini перегружен, тексты пишет бесплатная модель OpenRouter |
| `AZURE_SPEECH_KEY` | нет | запасная озвучка Azure (или основная, если `provider: azure`) |
| `AZURE_SPEECH_REGION` | нет | регион ресурса Azure Speech, например `westeurope` |
| `YT_CLIENT_ID` | да | OAuth-клиент Google |
| `YT_CLIENT_SECRET` | да | OAuth-клиент Google |
| `YT_REFRESH_TOKEN` | да | бессрочный доступ к каналу |
| `YT_API_KEY` | нет | поиск трендов, если OAuth не задан |
| `POLLINATIONS_TOKEN` | нет | бесплатный токен Pollinations — мягче лимиты |

### 2.1. GEMINI_API_KEY (бесплатно)

1. Откройте <https://aistudio.google.com/apikey> и войдите в Google-аккаунт.
2. Нажмите **Create API key** → выберите или создайте проект → скопируйте ключ.
3. Сохраните его как секрет `GEMINI_API_KEY`.

Бесплатного тарифа хватает с запасом: конвейер делает 3–10 запросов в день.
Модель выбирается автоматически: конвейер запрашивает у Google список доступных моделей и берёт новейшую
стабильную flash, а при перегрузке (ошибка 503 или таймаут) переходит на облегчённую flash-lite и псевдонимы
`gemini-flash-latest`. Старые модели Google отключает (например, `gemini-2.5-flash` к ноябрю 2026 отвечает 404),
поэтому жёсткий список не используется. Свою модель можно задать переменной `GEMINI_MODEL`.

### OPENROUTER_API_KEY (запасной поставщик текстов, бесплатно)

Вечером Gemini бывает перегружен (ошибки 503), и ролик не собирается. Запасной путь — бесплатные модели
OpenRouter (Gemma 4 31B, Nemotron 3 Ultra и др.; список берётся у OpenRouter автоматически).

1. Откройте <https://openrouter.ai> → **Sign in** (через Google, GitHub или почту). Карта не нужна.
2. Справа вверху меню → **Keys** → **Create Key** → имя `shorts` → **Create**. Скопируйте ключ (`sk-or-v1-…`).
3. Сохраните его как секрет GitHub `OPENROUTER_API_KEY`.

Лимиты бесплатных моделей: 20 запросов в минуту и 50 в день — запасному пути хватает (он включается только
когда Gemini не отвечает; после первого отказа Gemini весь запуск идёт через OpenRouter).

### 2.2. (необязательно) AZURE_SPEECH_KEY и AZURE_SPEECH_REGION

Azure не обязателен: по умолчанию озвучивает Vosk. Если у вас получится зарегистрироваться в Azure:

1. Зарегистрируйтесь на <https://azure.microsoft.com/free/> (нужна карта для подтверждения личности;
   за тариф F0 деньги не списываются).
2. Откройте <https://portal.azure.com> → **Create a resource** → найдите **Speech** (Azure AI services → Speech service) → **Create**.
3. Заполните:
   - **Resource group** — создайте новую, например `shorts`;
   - **Region** — ближайший, например **West Europe** (`westeurope`); запомните его;
   - **Name** — любое уникальное имя;
   - **Pricing tier** — **Free F0**.
4. **Review + create → Create**, дождитесь окончания развёртывания → **Go to resource**.
5. Слева **Keys and Endpoint**: **KEY 1** → секрет `AZURE_SPEECH_KEY`, **Location/Region** (например `westeurope`) → секрет `AZURE_SPEECH_REGION`.

Лимиты F0: 0,5 млн символов нейроголоса в месяц (ролик ≈ 1–3 тыс. символов вместе с разметкой →
30 роликов укладываются с большим запасом), около 20 запросов в минуту. Бесплатный ресурс F0 можно
создать только один на подписку.

### 2.3. Проект Google Cloud и YouTube Data API v3

1. Откройте <https://console.cloud.google.com/> → вверху выбор проекта → **New Project** → имя, например `shorts-bot` → **Create**.
2. **APIs & Services → Library** → найдите **YouTube Data API v3** → **Enable**.
3. **APIs & Services → OAuth consent screen** (или **Google Auth Platform**):
   - User type: **External** → **Create**;
   - App name, support email, developer email — любые ваши;
   - **Scopes / Data access → Add or remove scopes**: добавьте
     `https://www.googleapis.com/auth/youtube.upload` и `https://www.googleapis.com/auth/youtube.readonly`;
   - **Test users / Audience**: добавьте Google-аккаунт, которому принадлежит канал.
   - ⚠️ **Важно:** нажмите **Publish app** (статус **In production**). В статусе *Testing* refresh token
     перестаёт работать через 7 дней. Проходить проверку Google для личного использования не обязательно —
     при входе просто появится предупреждение «Google hasn't verified this app».
4. **APIs & Services → Credentials → Create credentials → OAuth client ID**:
   - Application type: **Desktop app** → **Create**;
   - скопируйте **Client ID** → секрет `YT_CLIENT_ID`, **Client secret** → секрет `YT_CLIENT_SECRET`.
5. *(необязательно)* **Create credentials → API key** → секрет `YT_API_KEY`.

### 2.4. YT_REFRESH_TOKEN

Делается один раз на своём компьютере (нужен браузер):

```bash
git clone <этот репозиторий> && cd <папка>
pip install google-auth-oauthlib
python -m src.get_refresh_token --client-id "ВАШ_CLIENT_ID" --client-secret "ВАШ_CLIENT_SECRET"
```

1. Откроется браузер — войдите в аккаунт **с тем каналом**, куда нужно публиковать (если каналов несколько — выберите нужный).
2. Предупреждение «Google hasn't verified this app» → **Advanced / Дополнительно → Go to … (unsafe) / Перейти**.
3. Разрешите доступ (загрузка видео и просмотр аккаунта YouTube).
4. В консоли появится `YT_REFRESH_TOKEN` — сохраните его как секрет.

Если порт 8080 занят — добавьте `--port 8090`.

### Проверка подключения YouTube
После того как секреты `YT_CLIENT_ID`, `YT_CLIENT_SECRET`, `YT_REFRESH_TOKEN` сохранены:
**Actions → YouTube check → Run workflow**. Ничего не публикуется — в логе появится
«✅ Подключено к каналу: «…»» или ошибка с подсказкой, что исправить.

### 2.5. Аудит YouTube API — не нужен

Раньше (с 28.07.2020) видео из непроверенных API-проектов принудительно становились приватными, и нужно было
проходить аудит Google. **2 ноября 2026 Google это правило отменил** — в
[истории изменений YouTube Data API](https://developers.google.com/youtube/data/revision_history):
«Videos uploaded through the videos.insert method from unverified API projects are no longer restricted to
private viewing mode». Ролики публикуются сразу публичными, анкету заполнять не нужно.

Если видео всё же оказалось приватным — проверьте настройки канала по умолчанию в YouTube Studio
(Настройки → Загрузка видео → Доступ) и `config/publish.json → privacy_status`.

Квота: загрузка видео считается в отдельной квоте (до 100 загрузок в сутки), поиск трендов — до 10 запросов
в сутки. Два ролика в день укладываются с огромным запасом.

### Режим «на проверку»
Чтобы ролики загружались приватными, а публиковали их вы вручную в YouTube Studio, поставьте
`config/publish.json → "privacy_status": "private"`. Сейчас стоит `public` — автопубликация.

### 2.6. POLLINATIONS_TOKEN (необязательно)

Без токена Pollinations работает, но ограничивает анонимов (≈ 1 картинка в 45 с с одного IP, ~576×1024).
Конвейер сам ждёт сколько нужно, поэтому шаг картинок может занять до ~10 минут.
Бесплатный токен: зарегистрируйтесь на <https://enter.pollinations.ai> → скопируйте ключ → секрет `POLLINATIONS_TOKEN`.

## 3. Голос, ударения и интонации

### Озвучка: как это устроено
- **Vosk TTS** (Apache 2.0) работает прямо на серверах GitHub Actions: без регистрации, ключей и лимитов.
  Голос выбран — `3` (`config/voice.json → vosk → speaker`, всего 5 голосов: 0–4).
- Каждая сцена озвучивается по фрагментам от narration-director: точные паузы (тишина нужной длины),
  темп по фрагментам, ударения «+» от RUAccent. Чтобы фразы не слипались, фрагменты дополнительно режутся
  на предложения и части фразы, между ними — гарантированная тишина: 400 мс после `. ! ? ...`,
  250 мс после `: ;` и перед тире, 450 мс между сценами. Если где-то всё равно слипается — увеличьте
  `config/voice.json → vosk → min_pause_*` (можно включить паузу после запятых: `min_pause_comma_ms`). Ключевые слова голосом не выделяются, интонация ровная.
- Тайминги слов для субтитров — **faster-whisper** (MIT) по готовой озвучке (в тесте 80–100% слов
  каждой сцены найдено, остальные достраиваются по соседям).
- Цифры и латиницу Vosk не читает: story-writer пишет все числа словами («в тысяча девятисотом году»),
  а на всякий случай остатки цифр переводятся в слова, латиница — транслитом, неподдерживаемые символы убираются.
- Запасные провайдеры (если Vosk упадёт): **Gemini TTS** (тот же ключ Gemini, вся история одним запросом) и
  **Azure** (если заданы его ключи). Порядок — `config/voice.json → provider`.
- Отказались: SaluteSpeech (с 15.07.2026 не подключает новых физлиц, бесплатно — только некоммерчески),
  Silero (CC BY-NC), Piper (неясная лицензия голосов). Qwen3-TTS (Apache 2.0) звучит живее, но голоса не
  русские и синтез в ~10 раз медленнее — можно добавить позже.

### Выбор голоса
**Actions → Voice test → Run workflow** (сервис `vosk`) → в артефакте `voice-test-N` все 5 голосов Vosk
и `index.html` с плеерами. Другой голос — впишите номер в `config/voice.json` → `"vosk"` → `"speaker"`.

### Ударения
- RUAccent расставляет «ё» и определяет ударения с учётом контекста (омографы: за́мок/замо́к, му́ка/мука́).
- **Омографы дополнительно проверяет Gemini**: для каждого такого слова он выбирает один из вариантов RUAccent
  по смыслу предложения. Пример: RUAccent ошибся в «Мука для хлеба» (му́ка), Gemini исправляет на «мука́».
- Vosk получает ударение знаком «+» перед гласной — проверено: «замок» без разметки он читает как «за́мок»,
  а «зам+ок» звучит иначе; RUAccent исправил ошибки Vosk в «тяжёлый замо́к» и «настоящая му́ка».
- Для Gemini TTS и Azure ударение передаётся знаком U+0301 (для Azure проверено, для Gemini TTS — нет).
- По умолчанию ударения ставятся только омографам и словам из словаря, остальное синтезатор читает сам
  (`config/voice.json → stress.mode`: `homographs` или `all`).
- **Ошибка в ударении? Добавьте слово в `stress_dict.json`:**
  ```json
  { "Эйлеан": "+Эйлеан", "все": "всё", "атлас": "атл+ас" }
  ```
  Ключ — слово как в тексте, значение — «+» перед ударной гласной (или вариант с «ё»).
- Проверить ударения на выбранном голосе: workflow **Voice test** с галочкой «Тест ударений»
  (`python -m src.voice_test --stress-test`): три варианта каждой фразы — без разметки, вручную, через RUAccent.

### Интонации и паузы (narration-director)
Gemini размечает историю как режиссёр озвучки: паузы 300–600 мс после хука, перед поворотом и перед
развязкой, 150–250 мс между смысловыми частями; чуть медленнее в напряжённых местах, чуть выше в вопросах;
выделение ключевых слов загадки.
- Для **Vosk** фрагменты, паузы и темп — в артефакте `narration/vosk_script.txt`.
- Для **Gemini TTS** паузы превращаются в теги `<short pause>` / `<long pause>`, ключевые слова пишутся
  ЗАГЛАВНЫМИ (так советует документация Google), а темп и настроение задаются описанием манеры чтения
  (`tts_style`). Текст для диктора — в артефакте `narration/gemini_tts_script.txt`.
- Для **Azure** из той же разметки собирается SSML (`narration/scene_XX.ssml`, `narration/full.ssml.txt`);
  он проверяется, при ошибке — откат на простой текст с паузами.
Диапазоны пауз, темпа и высоты — в `config/voice.json`.

## 4. Музыка

1. Откройте <https://pixabay.com/music/> → поиск `lofi` / `lo-fi chill` / `ambient`.
2. Скачайте 5–15 спокойных треков (MP3) и положите в папку `music/`, закоммитьте.
3. *(необязательно)* рядом с треком положите `<имя_трека>.txt` с атрибуцией — она попадёт в описание.

Каждый раз выбирается случайный трек, громкость ~12% (`MUSIC_VOLUME`), плавное затухание в конце.
Pixabay Content License разрешает бесплатное использование без указания авторства; на всякий случай
избегайте треков с пометкой о регистрации в Content ID. Если папка пуста — конвейер **синтезирует**
спокойный лоу-фай трек сам (`src/music_gen.py`), он гарантированно без авторских прав.

## 5. Расписание GitHub Actions

Файл `.github/workflows/daily.yml`:

- **слоты выхода по Москве** — `config/schedule.json`: по 17.11 — 17:00, 19:00 и 21:00 (3 ролика в день для набора аудитории), затем 19:00 и 21:00 — вечерний пик просмотров Shorts; ручной запуск публикует ролик сразу и слот не занимает. Сборка стартует примерно за 1 ч 40 мин, ролик загружается с отложенной публикацией (YouTube `publishAt`) и становится публичным ровно в слот; если слот уже прошёл — публикуется сразу.
  Запуски идут строго по очереди: второй начинается после того, как первый сохранил свою тему;
- если запуск упал из-за временной перегрузки сервисов, он повторяется один раз через 10 минут;
- **встроенный cron GitHub в этом репозитории не срабатывал** (11.11.2026 — ни одного запуска), поэтому
  основной запуск делает внешний будильник Claude Code (Routine «Shorts: запуск публикации по расписанию»,
  10:41, 13:41, 21:41, 23:41 МСК): он вызывает workflow с `scheduled=true`. Встроенные cron тоже оставлены;
- перед каждым плановым запуском **страж** (`src/schedule_guard.py`) считает ролики, вышедшие сегодня,
  на канале YouTube и в `publish_log.json`: до 18:00 МСК норма 1, после — 2. Лишние запуски завершаются
  за полминуты без публикации, пропущенные — догоняются;
- **вручную**: вкладка **Actions → Daily YouTube Short → Run workflow**. По умолчанию галочка
  «Не загружать на YouTube» включена — это безопасный тестовый прогон. Можно включить тестовую рекламу и задать тему.

Что получаете:

- артефакт `short-N`: `final.mp4`, картинки сцен, `story.json`, `storyboard.json`, `metadata.json`, `subtitles.srt`, `summary.json`;
- артефакт `trends-report-N`: `trends_report.json` (тема, источник, метрики, причина выбора, топ-15 кандидатов);
- после публикации бот коммитит `used_topics.json`, `publish_log.json`, `ads/log.json` (темы не повторяются,
  а коммиты не дают GitHub отключить расписание за неактивность).

Если пуш бота падает с 403: **Settings → Actions → General → Workflow permissions → Read and write permissions**.

Время запуска меняется строкой `cron` (время в UTC).

### Концовка «лайк и подписка»
В конце каждого ролика (~4 с) голос просит поставить лайк и подписаться, а поверх затемнённого последнего
кадра идёт анимация: заголовок, кнопка лайка, кнопка «ПОДПИСАТЬСЯ», палец-курсор нажимает обе
(лайк синеет, подписка меняется на «ВЫ ПОДПИСАНЫ», колокольчик качается). Тексты и вкл/выкл —
`config/cta.json`, анимация — `src/cta.py`, значки — `assets/cta/` (Noto Color Emoji, OFL).

**Ваш голос в концовке.** Положите 3–5 записей просьбы подписаться в `assets/cta/voice/` (mp3/m4a/wav/ogg, 2–6 с). В каждом ролике берётся случайная запись (не та же, что в прошлом), тишина по краям обрезается, громкость выравнивается под озвучку. Пустая папка — концовку читает Vosk.

### Ролики не повторяются
Тематика общая (тайны и загадки), но каждая история уникальна. Защита в три уровня:
1. **Текст темы** сравнивается со всеми прошлыми темами в `used_topics.json`.
2. **Смысл темы** проверяет Gemini: тот же случай, явление, место, человек или артефакт под другим названием
   («Перевал Дятлова» = «гибель туристов на Урале в 1959») — отклоняется.
3. **Готовая история** сравнивается с прошлыми по ключевым словам. Порог откалиброван: разные загадки дают
   сходство ≤ 0,08, пересказ той же истории ≈ 0,19, отсекается всё выше 0,14. Похожая история отбрасывается,
   выбирается другая тема (до 3 попыток).

Если тренды не дали новой темы, Gemini сам предлагает свежую реальную загадку, которой ещё не было.
Отклонённые темы и причины видны в `trends_report.json → rejected`.

## 6. Реклама (по умолчанию выключена)

Конфиг — `ads/config.json`:

```json
{
  "enabled": false,
  "opacity": 0.9,
  "fade": 0.5,
  "max_banner_width": 720,
  "max_banner_height": 300,
  "label": "Реклама",
  "campaigns": [
    {
      "id": "romashka-20261110",
      "enabled": true,
      "advertiser": "Ромашка",
      "legal": "ООО «Ромашка», ИНН 0000000000",
      "erid": "2Vtzqxxxxxx",
      "banner": "ads/romashka-20261110.png",
      "url": "https://example.com/?utm_source=shorts",
      "start_date": "2026-11-10",
      "end_date": "2026-12-10",
      "position": "auto",
      "show_at": 20,
      "duration": 5
    }
  ]
}
```

| Поле | Значение |
|---|---|
| `position` | `auto` (ищет самую «пустую» область в верхней половине), `top-left`, `top-center`, `top-right`, `upper-middle` или `{"x": 100, "y": 300}` |
| `show_at` | секунда появления (не раньше 3.5 с — хук не трогаем; пусто = 40% ролика) |
| `duration` | 4–6 секунд |
| `legal`, `erid` | данные для маркировки рекламы (ФЗ «О рекламе»: «Реклама», рекламодатель, токен ОРД) |

### Как включить рекламу

1. Добавьте кампанию (баннер копируется в `ads/`):
   ```bash
   python -m src.ads add --banner ~/Downloads/banner.png --advertiser "Ромашка" \
       --url "https://example.com" --start 2026-11-10 --end 2026-12-10 \
       --legal "ООО «Ромашка», ИНН 0000000000" --erid "2Vtzq..."
   ```
2. Проверьте на последнем готовом видео:
   ```bash
   python -m src.ads test --campaign romashka-20261110
   ```
   Посмотрите `output/ad_test_*/ad_preview.jpg` и `video_ad.mp4`.
3. Включите: `python -m src.ads enable` (или `"enabled": true` в конфиге), закоммитьте `ads/`.

Можно просто прислать баннер Claude Code в чат — он сделает шаги 1–2 сам (скилл `ad-inserter`).

### Что гарантирует модуль

- Баннер только в безопасной зоне Shorts: верх кадра под шапкой (y 210–900), не перекрывает субтитры,
  правую колонку кнопок и нижнюю подпись; даже ручные координаты зажимаются в эту зону.
- Непрозрачность 90%, плавное появление и исчезновение, показ 4–6 с, не в первые 3 секунды.
- Плашка «Реклама» на баннере, в описании первой строкой «Реклама. Рекламодатель: … erid: …» и ссылка.
- В YouTube ставится отметка о платной рекламе (`paidProductPlacementDetails.hasPaidProductPlacement`).
  Если API её не принял — в логе будет предупреждение, поставьте галочку в YouTube Studio вручную.
- Кампании с истёкшей датой пропускаются; при нескольких активных — ротация (меньше показов → раньше).
- Каждый опубликованный показ пишется в `ads/log.json`. Отчёт рекламодателю: `python -m src.ads report --campaign ID`.
- Прочие команды: `python -m src.ads list`, `python -m src.ads disable`.

## 8. Если что-то пошло не так

- **Тема повторяется** — проверьте, что бот коммитит `used_topics.json` (права на запись, см. п. 5).
- **Gemini TTS: дневной бесплатный лимит исчерпан** — подождите сутки; не запускайте тест всех 30 голосов в день публикации.
- **Azure: AuthenticationFailure (401)** — неверный ключ или регион (регион — код вида `westeurope`, не название).
- **Azure отверг SSML** — конвейер сам повторит с простой разметкой (текст + паузы); подробности в логе.
- **Неправильное ударение** — добавьте слово в `stress_dict.json` (п. 3).
- **Видео загрузилось приватным** — проверьте `privacy_status` в `config/publish.json` и настройки доступа по умолчанию в YouTube Studio (п. 2.5).
- **invalid_grant** при загрузке — refresh token отозван или истёк (приложение в статусе Testing, п. 2.3) — получите новый.
- **Reddit / Google Trends недоступны** — источник пропускается, тема выбирается из оставшихся.
- Подробности каждого запуска — `output/<run>/summary.json` (время шагов, ошибка с трассировкой).

## Режим «живой голос» (выключен)

Историю читает автор канала, всё остальное делает конвейер. Включение: `config/human_voice.json` → `"enabled": true`.

1. Запуск по расписанию готовит сценарий: `inbox/<id>/script.md` (текст по сценам + ударения в трудных словах) и создаёт issue «🎙 Начитать: …» — GitHub пришлёт уведомление.
2. Вы читаете текст целиком одной записью (диктофон или голосовое) и загружаете файл в `inbox/<id>/` (на GitHub: Add file → Upload files).
3. Ближайший запуск находит запись, распознаёт её, делит на сцены, собирает ролик с картинками, субтитрами и концовкой и публикует в слот. Папка сценария после публикации удаляется.

Пока записи нет — ролик в этот слот не выходит. Если записи нет дольше `fallback_after_hours` (24 ч), сценарий выходит с голосом Vosk (`"fallback": "vosk"`) или продолжает ждать (`"wait"`). `queue_size` — сколько сценариев держать готовыми к начитке.

## Пробный ролик со всеми улучшениями (`pilot`)

Actions → Daily YouTube Short → Run workflow: `no_upload` = false, `pilot` = true (рубрика — `mystery`, `versions` или `myth`, пусто — по кругу). Ролик загружается **по ссылке (unlisted)** и не занимает слот расписания. Включается всё из `config/quality.json`: справка из Википедии и «Источники» в описании, вывод автора и вопрос зрителю, рубрика с плашкой, настоящие архивные фото из Wikimedia Commons с авторством, водяной знак канала. Чтобы включить это для всех роликов — `"enabled": true`.
